# 飞书需求入口 UI 设计

## 目标

在议题看板右侧工具区增加一个始终可识别的飞书需求入口，让用户能从当前看板直接完成首次接入或拉取最新需求。

## 真实操作路径

`议题看板顶部工具栏 -> 点击飞书需求入口 -> 未配置时打开 FeishuConnectionDialog；已配置时调用 syncFeishuConnection -> 刷新项目与当前任务数据 -> 看板显示最新数据并出现“飞书需求已同步”提示`

涉及的现有实现：

- 入口与状态分流：`web/src/App.tsx`
- 飞书接入弹窗：`web/src/components/FeishuConnectionDialog.tsx`
- 同步请求：`web/src/api.ts` 中的 `syncFeishuConnection`
- 同步数据写入：`server/feishu-integration.mjs` 中的 `syncWithView`
- 视觉样式：`web/src/styles.css`

## UI 与状态

- 入口位于议题看板二级工具栏右侧，排列在搜索入口之前。
- `feishuConnection.configured === false` 时，显示链路图标和“接入飞书需求”。点击后打开现有接入弹窗，继续授权和需求视图配置。
- `feishuConnection.configured === true` 时，显示刷新图标和“同步飞书需求”。点击后直接运行现有同步函数，不打开授权弹窗。
- 同步进行中时按钮不可重复点击，文案显示“同步中…”，刷新图标旋转。
- 同步成功沿用现有全局提示“飞书需求已同步”；失败沿用现有看板错误提示。
- 项目菜单中的“飞书需求设置”保留，用于用户主动修改授权或需求视图。
- 飞书项目在议题看板中不再同时显示标题栏的图标同步入口；列表和甘特图仍保留原图标入口。

## 响应式行为

- 桌面宽度显示图标和完整文案。
- 窄屏下仅显示状态图标，通过动态 `aria-label` 和原生提示保留完整动作名称，避免挤压视图标签与搜索控件。

## 范围

本次只复用现有授权、配置、同步和提示能力，不修改飞书 API、配置格式、同步规则、数据模型或项目切换行为。按项目规则，在用户确认直接路径前不新增回归测试或额外保护逻辑。

## 直接验证

1. 未配置状态：议题看板显示“接入飞书需求”，点击后打开 `FeishuConnectionDialog`。
2. 已配置状态：议题看板显示“同步飞书需求”，点击后直接发起同步，不打开授权弹窗，并显示同步中和成功状态。
3. 桌面与窄屏：入口、视图标签、搜索和筛选控件无重叠或文字溢出。
